# ADR-0002: 取り込みバッチを reader・transformer・writer の 3 段に分ける

- ステータス: 採用
- 日付: 2026-01-01
- 階層: アプリ
- 対象: `apps/importer`(書式の例示用。実在の決定ではない)
- 上位: ADR-0001

## コンテキスト

複数の情報源(アプリログ、監査ログ、業務システムの処理履歴)のイベントを取り込み、共通の形式で DB に保存する(ADR-0001)。
情報源ごとに形式が異なり、情報源は今後も増える。変換の規則は、情報源や DB を用意せずにテストしたい。

### 検討した選択肢

| 案 | 却下理由 |
|---|---|
| 情報源ごとに、読み込みから保存までを 1 つの処理に書く | 変換の規則が入出力のコードに混ざり、単体でテストできない。保存の処理が情報源の数だけ重複する |
| ヘキサゴナルアーキテクチャ(入出力をすべてポートにする) | 入力と出力が 1 種類ずつのバッチでは、インターフェースが増えるだけで得るものが少ない |

## 決定

**取り込みバッチを、reader・transformer・writer の 3 段のパイプラインにする。transformer は入出力を持たない純粋な関数にし、段の間は共通のイベントの型だけで受け渡す。**

判断の根拠:

1. **変換の規則を単体でテストできる。** transformer は、値を渡して戻り値を比べるだけでテストできる。
2. **情報源を足すときの変更が reader に収まる。**

### 構成要素

置き場所は `apps/importer/src/` からの相対パス。

| 構成要素 | 置き場所 | 責務 |
|---|---|---|
| 起動 | `main.ts` | 3 段を組み立てて実行する |
| reader | `readers/` | 情報源からの読み込み。情報源ごとに 1 つ |
| transformer | `transformers/` | 情報源の形式から、共通のイベントへの変換 |
| writer | `writers/` | 共通のイベントの DB への保存 |
| イベントの型 | `events/` | 段の間で受け渡す、共通のイベントの型 |

### 依存の規則

表にない依存は禁止する。

| 構成要素 | import してよいもの |
|---|---|
| 起動 | reader・transformer・writer |
| reader | イベントの型。情報源のクライアント |
| transformer | イベントの型 |
| writer | イベントの型。DB のクライアント |
| イベントの型 | なし |

### 接続の規則

| 対象 | 必須 | 禁止 |
|---|---|---|
| 段の受け渡し | 起動が、reader の出力を transformer に、その出力を writer に渡す | 段が、ほかの段を直接呼ぶ |
| transformer | 引数だけから戻り値を決める | 入出力(ファイル、ネットワーク、DB、現在時刻)を扱う |

## 結果

- 良い面: 変換の規則を、情報源や DB なしでテストできる。情報源の追加が reader と transformer の追加で済む。
- 受け入れた不利益: 1 件ずつ段を通すので、情報源の側でまとめて処理できる場合より遅い。
- 未解決の保留事項: なし。
- 移行作業: 上の依存の規則を lint で検査する。
