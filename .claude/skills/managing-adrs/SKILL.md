# ADRの作成・更新

対象は実装上の技術選定のみ。ブランチ運用・コミット規約・PRフローなどの開発プロセスは書かない。
一覧ファイルは作らない。有効な決定は次で調べる。

```sh
grep -H "^- ステータス:" docs/adr/*.md
```

## テンプレート

- 書式: [`TEMPLATE.md`](./TEMPLATE.md)
- 記入例: [`SAMPLE.md`](./SAMPLE.md)

## ステータス

| 値 | 意味 | 実装の根拠にしてよいか |
|---|---|---|
| 提案中 | まだ合意していない | ✗ |
| 採用 | 現在有効な決定 | ✓ |
| 却下 | 検討したが採らなかった | ✗ |
| 非推奨 | まだ動いているが、新規には適用しない | 既存の説明としてのみ |
| 置換済み（ADR-XXXX） | 後続ADRに置き換えられた | ✗ |

ステータスは値だけの記述にする（但し書きを付けない）。

## 新規作成

1. `ls docs/adr/ 2>/dev/null` で最大番号を確認し、次の連番を採る（欠番は再利用しない。無ければ `docs/adr/` を作り `0001` から）
2. `TEMPLATE.md` をコピーして `docs/adr/XXXX-kebab-case-title.md` を作る
3. `./scripts/check-adr-format.sh docs/adr/XXXX-*.md` が通るまで直す

## 決定が変わったとき

採用済みADRの「コンテキスト」「決定」は書き換えない。

1. 新しいADRを起こす
2. 旧ADRのステータスを `置換済み（ADR-XXXX）` へ変える

例外: 誤字・リンクの修正と、「結果」への追記。

## 書くときの注意

- 「結果」には次を記載する
  - 良い面
  - 受け入れた不利益
  - 未解決の保留事項
  - 必要な移行作業
- 単独のADRを起こすほどでない補足は、次の1文を該当ADRの「結果」へ追記する

> \<コンテキスト\> において \<懸念\> のため、\<選択肢\> のうち \<決定\> を採る。\<期待する効果\> を得るため、\<受け入れる不利益\> を許容する。
