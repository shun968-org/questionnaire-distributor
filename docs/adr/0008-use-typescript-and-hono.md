# ADR-0008: 画面と API を TypeScript で実装し、API に Hono を使う

- ステータス: 採用
- 日付: 2026-11-15
- 関連: ADR-0001、ADR-0009、ADR-0010、ADR-0012

## コンテキスト

ADR-0001 の決定から、アーキテクチャ(構造・レイヤ間の接続方法)に関係しない項目(拡張子・`tsconfig` の設定・TypeScript 以外のファイルの例外の一覧)を外して作り直す。決定の内容は ADR-0001 と同じである。

治療計画に連動した質問票の配信スケジュールを設定する管理画面と、その値を PostgreSQL に読み書きする API を作る。
当初は API を Go(Echo)で書く想定だったが、DB アクセスに Prisma を使い、学習目的も満たしたい(ADR-0009)。
Go 用の Prisma Client は Prisma の新しいバージョンに対応せず、非推奨になる予定である。

### 検討した選択肢

| 案 | 却下理由 |
|---|---|
| API を Go(Echo + sqlc)で書き、Prisma はスキーマとマイグレーションの管理だけに使う | Prisma Client を使わないので学習目的を満たさない。スキーマの管理が Node、実行が Go の 2 系統になる |
| 同じ API を Go 版と TypeScript 版の 2 つ作る | 実装量が約 2 倍になる |

## 決定

**画面と API をどちらも TypeScript で実装し、API の HTTP サーバには Hono を使う。**

判断の根拠:

1. **Prisma Client を使える。** 学習目的を満たす。
2. **言語が 1 つで済む。** 画面は API の型(Hono RPC の `AppType`)を `import type` で参照でき(ADR-0010)、実装量が一番少なくなる。

### 規則

| 対象 | 必須 | 禁止 |
|---|---|---|
| リポジトリの構成 | アプリケーションのコードは `apps/web`(画面)と `apps/api`(API)に置き、TypeScript で書く | TypeScript 以外の言語でアプリケーションのコードを書く |
| `apps/api` | HTTP の受付は Hono で行い、Node 上で起動する | Hono 以外の HTTP フレームワークを入れる |

## 結果

- 良い面: 画面と API が 1 つの言語になり、API の型を画面からそのまま参照できる。
- 受け入れた不利益: Go を使う経験は得られない。
- 未解決の保留事項: なし。
- 移行作業: なし。ADR-0001 の規則のうち外した項目(拡張子・`tsconfig` の `strict`)は、`apps/` を作るときの設定で扱う。
